# 元素入场 / 出场动画（dsh-step-slide-in）

DSH 插件：监听整个 DOM。新增元素沿「上级容器元素群的视觉中心 → 自身视觉中心」的连线从屏幕外飞入原位，落定前微微放大，随后弹性回弹落定；被删除的元素转成固定定位图层飞出屏幕。

**所有动画都是合成层动画（`translate` / `scale`），不写任何内联样式、不写高度/外边距/overflow，因此不会引起布局变化或内容跳动；即使动画事件丢失、插件异常或页面里加载了多份插件，元素也不会被留在屏幕外。**

## 现在的行为

1. **观察整个 DOM**：`MutationObserver` 盯住 `document.body` 的 childList + subtree，所有新增元素（除 `<script>`、`<style>`、`<svg>` 内部、`display:none`、纯 inline 盒）都会进入入场处理；所有被删除的元素都会进入出场处理。
2. **无内联状态的入场**：元素本来就在最终布局位置，插件只创建一条 WAAPI 动画——`translate` 从屏幕外回到 `0 0`，`fill: backwards` 让它在自己的延迟期间停在起始帧；动画结束后没有 forward fill，元素自然回到原位。**全程不写 `el.style`**。
3. **群心射线**：飞行方向 = 元素「实际视觉中心」减去「上级容器所有元素视觉中心的面积加权重心」。相邻元素因此从元素群的同一侧飞入/飞出（列表底部的新行从下往上、顶部的从上往下）；容器只有一个可测元素或重心退化时，回退到「视口中心」射线。正在飞行的兄弟按其静止布局盒参与重心计算。
4. **落定放大 + 弹性回弹**：单条 980ms 的 `scale` 动画完成整段落定——前 520ms 用所选缓动曲线从 1 长到 **1.05**（正好在落地点），随后 460ms 是阻尼弹簧采样关键帧（1.05 → 略小于 1 → 1）。动画终点就是 1，不带 forward fill，所以不会残留放大的元素。
5. **动画密度**：设置里可切换入场动画挂在哪个盒子上——元素自身 / 它的父容器 / 再上一层容器（出场始终由被删元素自己飞出）。同一批只保留最外层容器，多个子元素同时到达时容器只入场一次；正在上浮的容器不会被打断重飞。
6. **队列节流**：每批新增元素的起跳时间在 500ms 内均匀铺开（`delay = 500ms × 序号 / 本批数量`），大列表不会同一帧全部起飞。
7. **出场走固定层幽灵**：元素被删除后，在本 microtask 内插回原槽位量一次位置，随即改为 `position: fixed` 放进幽灵层并飞出屏幕。插回→量测→移出全部发生在同一 microtask，浏览器不会绘制中间态，所以布局是瞬时塌陷的，动画本身不再移动任何兄弟元素。任何一步失败就直接把这枚已删除的节点丢弃，绝不会留下盖在界面上的图层。
8. **切换对话**：整屏替换时用删除前缓存的可视几何直接生成幽灵（不插回、不进新对话的流），最多 48 个。判断规则：同一批 mutation 里「新增了会话单元 + 删除了会话单元」即视为整视图替换。
   缓存只保存会话单元（`[data-chat-anchor-key]` / `[data-chat-call-id]`）的视口矩形：内容稳定后、滚动后、以及 `pointerdown`/`mousedown`/`keydown`/`wheel` 时刷新（点击侧栏切会话之前就抓好了几何）；缓存跨插件热重载保留；若缓存帧之后滚动过，会按滚动差补正坐标。
9. **不做退出动画的情况**：同一批里刚插入又删除（从未绘制过）、还在入场的节点、纯 inline 标签（span/a/code 等）、超出根节点/子树/高度上限的大块删除。
10. **重复添加不会二次入场**：还在飞行的元素再次进入 mutation 时直接跳过；入场动画只由动画自身负责隐藏与归还，没有需要「还原」的内联状态。
11. **页面只认一个实例**：客户端模块可能被重复求值（插件热重载、重复注册）。新实例启动时先接管并销毁上一个实例（断开观察器、释放滚动守卫、清掉幽灵），之后所有动画仍由 WAAPI 自己收尾。
12. **超时兜底**：仍持有真实状态的两样东西——滚动条守卫和幽灵图层——都有截止时间，1s 一次的巡检会在超时后强制释放（`diag.recovered` 记录次数）。入场元素不需要兜底：它们的动画结束就自然回到原位。
13. **位置自适应**：飞行只用相对元素自身位置的 `translate`，布局途中被顶动时元素跟着布局走；起跳距离按冻结时的位置计算，方向沿用群心射线。
14. **滚动条守卫**：入场的屏幕外位移会撑大祖先的滚动溢出，飞行期间临时冻结相关滚动容器的 overflow——本该可见的竖向滚动条保持可见，横向滚动条不会闪现；飞行结束后原样恢复。每个祖先的 computed overflow 在每批里只读一次。
15. **启动保护**：单个 mutation 批次超过 1200 个元素时跳过入场动画（应用启动、切换整屏视图），避免大面积开销。
16. 尊重系统「减少动态效果」：开启后完全不动画。
17. **可选 Swarm Cursors 模式**（默认关闭）：开启后入场改由一群光标接力完成——按元素类型分别用十字准星拖选框、I-beam 打字、钢笔描线，元素随即显形，光标离场。关闭时上面的 1–16 条一字不差地照旧；出场动画两种模式完全一致，永远是原版飞出。详见下节。

## Swarm Cursors 模式

设置里的「Swarm Cursors 模式」开关。关着的时候，这个子系统连一个 DOM 节点都不会创建。

开启后，每一批新元素的入场改由光标编舞。**编舞分四种模式，按元素自己的 DOM 特征自动选择**——参考实现里「建矩形 / 放图片 / 打字 / 画线」本来就是不同的动作，这里也照做，不是所有元素都用同一种：

| 模式 | 判定条件 | 光标做什么 |
| --- | --- | --- |
| `rect` 矩形 | 其余所有情况 | 十字准星 → 按下 → 沿对角线拖出选框 → 元素显形 |
| `image` 图片 | `img` / `picture` / `canvas` / `video` / `iframe`；`svg` 且 `role` 为 `img` 或 `presentation`；计算样式带 `background-image`；唯一子元素是图片标签 | 同矩形，但选框画完后**停留更久**（系数 0.22 对 0.15），和参考实现给图片多留的那点时间一致 |
| `text` 文本 | 叶子节点，没有元素子节点、但至少有一个非空白文本节点 | 十字准星飞到左上角 → 单击（或宽度 ≥ 140px 时拖出第一行选框）→ 换成 **I-beam** 光标，逐字移动「打字」→ 恢复箭头 → 撤掉选框 |
| `line` 线条 | `hr` | **钢笔**形状（`pen-add` 带加号，落笔后转 `pen`）→ 沿元素走四个点、逐点点击 → 恢复箭头 |

几条共通的约束：

1. 一批入场最多派 **6 组**光标（每组 1 个领队 + 2 个护航），领队之间不会抢同一个元素。每个元素的模式在入队时解析一次，画的时候不再重算。
2. 选框是蓝色 1px 描边 + 四角控制点 + 尺寸徽标（`宽 × 高`，宽高都 ≥ 8px 才显示）。
3. **元素会动，光标和选框跟着动**。所有关键坐标（起点、终点、按住位置、选框本身）都是每帧重新读取 `getBoundingClientRect()` 的函数，不是一次性算好的常数——元素在入场过程中被重排、被滚动、被别的动画推走，正在画它的光标和已经画好的选框都会贴住新坐标。测试里专门覆盖了这条（把元素从 100,100 移到 420,300，断言选框跟着到新位置）。
4. 文本模式**不改写页面 DOM**：元素照旧按自己的动画时钟淡入，光标只是在正确的位置表演打字。插件全程不碰页面元素的文本、不写内联样式，这条承诺在 swarm 模式下也成立。
5. 护航光标按参考实现的 boids 轨道物理绕着领队游动，领队离场时一起散开。
6. **显形时机由墙钟决定，不由帧率决定**：每个元素的显形动画都带自己的 `delay`，就算标签页被节流、rAF 掉帧，元素也会准时出现。剩余时间不够画完整套动作时自动降级——先退化成「准星点一下选框闪一下」，再不够就完全跳过编舞、让元素按原计划显形。
7. **光标层是一个挂在 `body` 上的 `position: fixed` 容器，带 `data-dss-skip="1"`，内部是 closed shadow root**。因此：页面的 CSS 选择器够不到它；插件自己的 `MutationObserver` 看不到它的 DOM 变化（不会递归）；它也永远不会被当成入场/出场目标。
8. **用完即弃**：入场队列、领队、护航全部清空后再停留 420ms，整层 DOM 被移除、`requestAnimationFrame` 停止。空闲时零开销。
9. 光标层创建失败（例如环境不支持 `attachShadow`）时，本批自动回退到原版飞入，并先取消已经建立的显形动画，不会出现两套入场互相抢 `opacity`。
10. 出场**完全不受影响**：两种模式下退出都还是原版的幽灵飞出。

## 设置

设置 → 通用 → 元素入场动画。

- 预设：平滑 / 标准 / 回弹 / 匀速。
- 自定义：点「自定义」展开曲线画布，拖两个控制点；方向键微调，Shift 加大步长。
- 曲线即时生效，影响之后启动的入场飞行与出场飞出（落定弹簧使用固定阻尼曲线）。
- 动画密度：元素 / 父容器 / 父级父容器。决定入场动画挂在哪个盒子上——「元素」每个新元素各自入场；「父容器」改为让新元素的父容器入场；「父级父容器」再上一层。同一批里只保留最外层容器，多个子元素同时到达时容器只入场一次，已经在上浮的容器不会被打断重飞。出场不受影响，始终由被删元素自己飞出。
- Swarm Cursors 模式：关闭 / 开启。开启后入场改为光标编舞（见上节），出场不变。默认关闭；切换立即生效，只影响之后启动的入场批次，已经在飞的元素照原计划收尾。

## 兼容性

针对 DSH `0.2.1-rc.3` 的 Chat DOM 与滚动容器（`[data-conversation-scroll]` 等）。插件不依赖混淆类名：动画基于标准 DOM API（`MutationObserver`、`Element.animate`、CSS `translate` / `scale` 独立变换属性），滚动条守卫基于计算后的 `overflow` 判定。竖式折叠组展开不再做高度动画（高度动画属于布局动画）。DSH 大版本更新后如果滚动容器或 Chat 结构变化，需要复核滚动条守卫是否仍覆盖新的滚动区。

## 安装

### A. 本地目录

1. 解压到固定位置，例如 `C:\\dsh-plugins\\dsh-step-slide-in`。
2. DSH → 设置 → 插件 → 添加插件，粘贴含 `package.json` 的目录路径。
3. 安装后刷新窗口或重启 DSH。

不要删除或移动这个文件夹：DSH 会以链接方式引用它。

### B. npm

```bash
cd dsh-plugins/step-slide-in
npm login
npm publish --access public
```

### C. GitHub

把本目录推到公开仓库，安装时填仓库地址。

## 诊断

按 `Shift+Alt+D` 可开关一个左上角的小黑面板，里面是实时计数：

- `version`：当前插件版本（用来确认页面加载的是哪一份代码）
- `cached`：缓存里有多少个可见会话单元；`cachedScroll`：缓存时的滚动位置
- `removals` / `roots`：最近一次删除观察到的节点数 / 顶层根数
- `density`：最近一批入场动画的承载层级（`element` / `parent` / `grandparent`）
- `mode`：`ghost`（单批删除，插回量测后转固定层）/ `ghost-cached`（整视图替换，
  用缓存几何）/ `ghost-empty`（走了缓存路径但没命中）/ `none`（本批没有可动画的删除）
- `ghosts`：最近一批实际生成的幽灵数量；`ghostsLive`：当前还活着的幽灵层
- `flying`：当前仍在飞行的元素数（滚动守卫持有者）
- `recovered`：超时巡检强制释放守卫/幽灵的次数（正常应为 0）
- `errors`：mutation 处理中捕获的异常次数
- `swarm`：当前设置里 Swarm Cursors 模式是否开启；`swarmMode`：`running`（光标层在跑）/ `idle`（已收工、层已移除）/ 空串（从没跑过）
- `swarmCursors`：当前活着的光标数（领队 + 护航）；`swarmUnits`：还没被光标领走的入场元素数
- `swarmRevealed`：光标完整画完选框的次数；`swarmDegraded`：因为剩余时间不够而降级（改成点一下或直接跳过编舞）的元素数

模式是逐元素判定的，所以同一批里可以同时出现 `rect` / `image` / `text` / `line` 四种编舞，`swarmRevealed` 数的是画完的次数而不是批次数。

## 性能与稳定性说明

- **零布局动画**：不写 `height` / `minHeight` / `margin` / `overflow`，不使用 `interpolate-size`；入场与出场都只提交合成层属性，主线程不因动画触发布局。
- **零内联样式**：入场不写 `el.style`，只有一条带 `delay` + `fill: backwards` 的 WAAPI 动画；一场动画自然收尾，不需要在结束时还原任何样式。这也是「元素不可能被留在屏幕外」的根本保证。
- **每批一次布局读取**：一批新增元素统一读几何与群心（每个容器只算一次重心，子元素超过 160 个按步长采样），然后统一创建动画。
- **祖先计算缓存**：滚动条守卫的 `getComputedStyle` 在每批里按祖先去重，共享祖先只读一次。
- **曲线字符串缓存**：缓动曲线按设置变更缓存，不再每个元素重建一次。
- **无属性观察**：MutationObserver 只观察 childList（折叠组展开的高度动画已移除），mutation 记录更少。
- **出场不再重排**：单批删除最多把节点插回量测一次（同一 microtask 内完成），整视图替换直接读缓存，完全不碰实时流。
- **密度去重**：父容器 / 父级父容器档把同一批的多处新增合并成一次容器动画（模拟里 350 个元素压缩成 32 个动画目标），不为每个子元素创建动画。
- **极简巡检**：1s 一次，只遍历还在飞行的守卫记录与幽灵层（通常个位数）。
- 单批入场上限 1200 个元素（队列上限 4000）；单批删除最多 24 个根节点、子树最多 400 元素；整屏替换最多 48 个幽灵。
- 每个处理过的删除只会尝试一次退出；不会因为「插回 → 放弃 → 再删除」产生 mutation 循环。
- **Swarm Cursors 模式的开销**：每批最多 6 组光标 = 18 个光标节点，每帧只做 18 次 `transform` 写入；选框与徽标按内容哈希比对，没变化就不写 DOM。整层在队列清空 420ms 后连同 rAF 一起销毁，所以不开关时零成本、开启后也只在入场期间有成本。跟随元素移动是每帧重读 `getBoundingClientRect()`，只在有光标正在画框时才发生，一次最多 18 次读。
